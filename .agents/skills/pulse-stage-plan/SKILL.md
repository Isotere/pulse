## Детализация этапа

Опиши:

- исходную точку и подтверждённые входы;
- проблему и назначение этапа;
- границы: что входит и что сознательно отложено;
- ожидаемый пользовательский, инженерный, учебный и предметный результат;
- последовательность работы;
- проверяемые критерии завершения;
- основные риски и неизвестные данные;
- раздел для фактического результата.

Планируй ближайший целостный срез на 1–2 месяца работы одного человека. Не пытайся спроектировать весь Pulse.

## Разбиение на задачи

Каждая задача должна:

- давать один наблюдаемый результат;
- иметь понятные входы и критерий завершения;
- быть выполнимой пользователем вручную за разумное время;
- учитывать текущий опыт в Rust и допускать рост сложности по ходу этапа;
- не содержать готового решения, кода или детальной реализации без прямого запроса;
- зависеть только от уже выполненных задач или явно названных входов.

По умолчанию добавляй список задач в документ этапа. Отдельные файлы или GitHub Issues создавай только по прямому запросу и только после согласования разбиения. Не создавай десятки задач для далёкого будущего.

## Проверка завершения

Сопоставь критерии с файлами, командами, тестами и наблюдениями. Верни одно решение:

- этап завершён;
- этап не завершён: назови конкретный недостающий результат;
- критерий больше не нужен: объясни, почему.

Не требуй отчёт ради отчёта. Пока результат не получен, работа продолжается через практику, обучение и исправление. Раздел «Фактический результат» заполняй только подтверждёнными сведениями.

Изменяй документы только по прямому запросу пользователя.
